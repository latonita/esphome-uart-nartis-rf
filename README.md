# Виртуальный мост UART <-> RF433-2 (Nartis 2024+) для ESPHome

**Назначение**: счётчики электроэнергии Нартис И100/И300/И500 (протокол "RF-433-2")
через трансивер CMT2300A на ESP32.

Предполагается использование в комплекте с компонентом [esphome_dlms_cosem](https://github.com/latonita/esphome-dlms-cosem)

Компонент, который **предоставляет UART** (`uart::UARTComponent`), но передаёт
каждый запрос/ответ по радиоканалу 433/443 МГц (CMT2300A), вместо проводов.
Любой компонент, умеющий общаться со счётчиком по «UART», может подключиться к
этому мосту — указав в своём `uart_id` его идентификатор — и работать без
изменений с радиосчётчиком. 

Частота канала выбирается автоматически согласно серийному номеру счётчика.

Мост **полностью прозрачен**: он отвечает только за радиотранспорт — внешнюю
обёртку кадра (синхронизация, поля длины, байт типа кадра, терминатор) и её
контрольную сумму CRC-16/X.25.

## Подключение (CMT2300A)

| Сигнал | Назначение |
| --- | --- |
| `pin_sdio` | данные SPI (MOSI/MISO) |
| `pin_sclk` | тактовый сигнал SPI |
| `pin_csb`  | выбор чипа (регистры) |
| `pin_fcsb` | выбор чипа (FIFO) |
| `pin_gpio3`| сигнал прерывания (INT2) |

## Конфигурация YAML

```yaml
external_components:
  - source: github://latonita/esphome-uart-nartis-rf
    components: [uart_nartis_rf]
    refresh: 1s

uart_nartis_rf:
  id: nartis_rf_uart
  address: "023240271060"   # серийный номер счётчика (12 цифр)
  pin_sdio: GPIO19
  pin_sclk: GPIO18
  pin_csb: GPIO5
  pin_fcsb: GPIO21
  pin_gpio3: GPIO22
  # request_gap: 100ms
  # rf_tx_timeout: 1000ms
  # rf_rx_timeout: 1000ms
  # rf_retries: 2
  # rx_center_offset: 758

# Компонент-счётчик, говорящий по UART, подключается к мосту вместо реального `uart:`.
# Пример настройки:
dlms_cosem:
  id: nartis_dlms
  uart_id: nartis_rf_uart

  client_address: 32  # Также в природе замечена рабочая конфигурация с клиентским адресом 17 и паролем "00000001"
  server_address: 1
  auth: true
  password: "00002080" # Пароль доступа. Ваш пароль может быть другим - проверьте паспорт на ваш прибор учета.


  receive_timeout: 5000ms
  update_interval: 300s
```

## Параметры конфигурации

- **id** (обязательно): идентификатор компонента. Укажите его в `uart_id`
  компонента-счётчика.
- **address** (обязательно, строка): серийный номер счётчика, ровно 12 цифр
  (например `"023240271060"`). По нему выбираются адрес и частота канала.
- **pin_sdio / pin_sclk / pin_csb / pin_fcsb / pin_gpio3** (обязательно): пины
  подключения CMT2300A (см. таблицу выше).
- **request_gap** (опционально, время): пауза, после которой запрос считается
  завершённым. По умолчанию `100ms`.
- **rf_tx_timeout** (опционально, время): таймаут передачи. По умолчанию `1000ms`.
  Используется как минимум: компонент автоматически увеличивает его на время
  передачи самого кадра (при 1.2 кбит/с — около 6.7 мс на байт), поэтому длинный
  запрос не будет прерван на середине.
- **rf_rx_timeout** (опционально, время): сколько ждать **первый байт** ответа за
  одну попытку. По умолчанию `1000ms`. Начавшийся кадр всегда докачивается до
  конца (полноразмерный кадр в 258 байт — это ~1.7 с эфирного времени).
- **rf_retries** (опционально, 0–10): сколько раз повторить запрос при потере или
  ошибке связи. По умолчанию `2`. Значение `0` полностью передаёт повторы
  компоненту-счётчику, который в отличие от моста понимает смысл запроса.
- **rx_center_offset** (опционально): тонкая подстройка частоты приёма. Значение
  по умолчанию `758` подходит для большинства случаев; менять только при
  проблемах со связью.
Ограничения размера (из-за однобайтового поля длины в радиообёртке): запрос — до
244 байт, ответ — до 252 байт.

Совет: задавайте таймаут приёма у компонента-счётчика (`dlms_cosem`) с запасом,
чтобы мост успел выполнить повторные запросы в случае помех в радиоэфире.
